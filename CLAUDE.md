# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## images-providok — контекст проєкту

Робочий репозиторій для інтернет-магазину на платформі **Horoshop** (він же Cartum,
help.horoshop.ua) — товари для FPV-дронів, авіамоделей, RC-хобі (кабелі, роз'єми,
сервоприводи, карбонові деталі). Це не кодова база (немає застосунку, який
компілюється/запускається) — це робоча тека з Excel-імпортами, фото товарів і
даними для аналізу/імпорту в адмінку Horoshop.

Репозиторій: https://github.com/feloniuk/images-providok

## Як продовжити роботу на новому ПК

1. `git clone https://github.com/feloniuk/images-providok.git`
2. Відкрити теку в Claude Code, ввести `/init` (доповнить цей файл автоматичними
   спостереженнями про структуру — сам файл вже містить весь предметний контекст,
   `/init` тут не обов'язковий, але не зашкодить).
3. Продовжувати роботу — весь контекст нижче.

**MCP-сервер Serena**: на момент останньої сесії (2026-08-07) Serena не мала
жодного зареєстрованого проєкту й жодної збереженої пам'яті для цього репозиторію
(`~/.serena/memories` порожня, `projects: []` у `~/.serena/serena_config.yml`).
Переносити з попереднього ПК нічого — на новому ПК просто активуйте Serena для
цього проєкту заново, якщо вона знадобиться (це не Node/Python кодова база з
LSP-аналізом, тому практичної потреби в Serena тут, ймовірно, немає).

## Що є в репозиторії

### Фото товарів
- `photos/` (228 файлів, ~44MB) — основна тека фото товарів магазину, іменовані
  за артикулом (напр. `10316.jpg`). Це джерело правди для фото.
- `photos_part1.zip`, `photos_part2.zip`, `photos_part3.zip` — застарілі архіви
  тих самих фото (перевірено: рівно ті самі 228 імен, що й у `photos/`, жодного
  унікального файлу). У `.gitignore` є правило `photos_part*.zip`, **але воно не
  діє** — усі три архіви були закомічені раніше й лишаються відстежуваними
  (`.gitignore` не розтрековує вже додані файли). Через це `.git` важить ~106MB
  при ~44MB корисних фото. Якщо користувач захоче це почистити — потрібен
  `git rm --cached photos_part*.zip` + коміт (історія лишиться роздутою, повне
  очищення потребує rewrite історії). **Не робити без явного прохання.**
- `missing_products_images/` (136 файлів) — фото для товарів, яких бракує на
  сайті (за списком з `missing_products_from_full2.xlsx`), іменовані
  `<артикул>@<номер>.jpg`.
- `download_images.py`, `download_log.csv` — скрипт масового завантаження
  фото товарів у `photos/` (з попередньої сесії, до появи цього CLAUDE.md).
  Читає колонки "Фото" (головне зображення) і "Галерея" (додаткові, `;`- або
  `\n`-розділені URL) з `e362b4e981110dc6a83c30d165c014c1 (1).xlsx`, зберігає
  як `<артикул>.<ext>` для головного і `<артикул>@N.<ext>` для галереї —
  та сама конвенція іменування, що й у `missing_products_images/`. Лог
  результату (OK/FAIL по кожному URL) пишеться в `download_log.csv`.
  Запуск: `python3 download_images.py` (потребує `openpyxl`).

  Обмеження скрипта, про які треба пам'ятати перед повторним запуском:
  - шлях до Excel, аркуш `Sheet1` та **індекси колонок захардкоджені**
    (`row[0]` — артикул, `row[15]` — Фото, `row[16]` — Галерея). У всіх наявних
    Horoshop-експортах (66/68/70 колонок) ці індекси досі збігаються, але при
    зміні структури експорту скрипт мовчки завантажить не те — звіряти заголовки
    перед запуском;
  - немає resume/пропуску вже завантажених — повторний запуск перезавантажує
    геть усе й перезаписує `download_log.csv`;
  - `download_log.csv` — результат минулого запуску (OK/FAIL по кожному URL),
    зручний, щоб знайти, які фото не долилися.

### Excel-файли: Horoshop імпорт/експорт кабелів (варіації товарів)
Задача: у магазині кожен провід/кабель — окрема картка (напр. "Провід 22 AWG,
червоний" і "Провід 22 AWG, чорний" — два різні товари). Мета — об'єднати такі
товари у варіації вибору (як color/size selector на маркетплейсах) через
реімпорт доопрацьованого Horoshop-файлу.

- `b359748195098e76b125920993b0164b.xlsx` — **оригінальний** повний
  експорт товарів з Horoshop (66 колонок, 196 рядків). Джерело правди,
  **не редагувати напряму**.
- `horoshop_import_variations.xlsx` — **результат**: копія оригіналу з
  проставленими "Родительский артикул" і "Название модификации (UA/RU)" для
  9 груп товарів (61 рядок об'єднано → 9 карток з варіаціями): термоусадочна
  трубка (колір), нейлонове обплетення (діаметр), провід силіконовий
  (переріз×колір, 16 рядків), провід монтажний супергнучкий (переріз×колір,
  13 рядків), 5 варіантів подовжувачів проводу JR/Futaba (варіація — довжина).
  Цей файл готовий для завантаження в Horoshop через Товари → Імпорт.
- `cables_horoshop_import.xlsx` — спрощений формат (без колонок варіацій,
  15 колонок) — **не підходить** для задачі варіацій, використовувався на
  ранньому етапі, лишений для довідки.

**Важливо (з'ясовано в сесії 2026-08-07):** сам факт заповнення "Родительский
артикул" + "Название модификации" в Excel **групує** рядки в один товар в
адмінці Horoshop, але **НЕ вмикає сам перемикач-кнопки на сторінці товару**.
Щоб кнопки з'явились на фронтенді, у адмінці Horoshop додатково потрібно:
1. Товари → Шаблони товарів → відкрити шаблон категорії → створити/перевірити
   характеристику (напр. "Колір", "Переріз AWG") з типом **"Вибір зі списку"**.
2. Виставити групу цієї характеристики як **"Модифікації"/"Variants"** і
   перетягнути її у форму вибору варіантів шаблону.
3. Проставити значення цієї характеристики кожному товару-варіанту (вручну
   або повторним імпортом, якщо після кроку 1 в експортному шаблоні з'явиться
   відповідна колонка).
4. Окремо, для фільтра в каталозі (не залежить від кроку вище): прив'язати
   значення кольору до "кольору для фільтра" в Товари → Значення атрибутів,
   і увімкнути характеристику в налаштуваннях фільтра категорії.

Джерело: офіційна документація help.horoshop.ua (Cartum Help Center),
стаття "Product Variants" (help.horoshop.ua/en/articles/4168442) та суміжні.
Це не покрито жодним файлом у репо — тільки описано тут і в історії діалогу.

## Команди

Тут немає збірки/тестів/лінтера — уся робота це Python + `openpyxl` над
Excel-файлами. Реально корисні команди:

```bash
# Розвідка будь-якого Horoshop-файлу: аркуші, колонки, к-сть рядків
python3 -c "
import openpyxl,sys
wb=openpyxl.load_workbook(sys.argv[1],read_only=True)
for ws in wb.worksheets:
    rows=ws.iter_rows(values_only=True); hdr=next(rows)
    print(ws.title,len(hdr),'колонок'); print(list(enumerate(hdr)))
" 'файл.xlsx'

# Стан варіацій: скільки рядків згруповано в батьківські картки
python3 -c "
import openpyxl,sys
ws=openpyxl.load_workbook(sys.argv[1],read_only=True).worksheets[0]
rows=list(ws.iter_rows(values_only=True)); hdr=rows[0]
data=[r for r in rows[1:] if r[0]]
p=hdr.index('Родительский артикул'); m=hdr.index('Название модификации (UA)')
ch=[r for r in data if r[p] and str(r[p])!=str(r[0])]
print(len(data),'рядків |',sum(1 for r in data if r[m]),'з назвою модифікації |',
      len(ch),'дочірніх у',len({str(r[p]) for r in ch}),'групах')
" 'файл.xlsx'

python3 download_images.py   # див. застереження в секції про фото вище
```

Ключова конвенція всіх Horoshop-експортів: аркуш завжди `Sheet1`, колонка 0 —
`Артикул`, 15 — `Фото`, 16 — `Галерея`. Кількість колонок (66/68/70) різниться
між експортами, тому **звертатись до колонок по імені заголовка, а не по
індексу**, скрізь, де це не успадкований код.

## Робочі інструменти

- `.agent-browser/` — тека для скріншотів браузерної автоматизації. Прописана
  в `.gitignore`, але **фізично відсутня** в цьому клоні (порожні теки не
  переносяться через git) — створити перед першим використанням браузера.
- `.claude/` у репозиторії немає — проєктних налаштувань/скілів/хуків не
  налаштовано, все працює на дефолтах Claude Code.
- У сесії використовувався виключно **claude-in-chrome** (вбудований інструмент
  Claude Code) для браузерної автоматизації — **не Playwright і не звичайний
  web-пошук**. Якщо це правило досі актуальне — дотримуватись його й надалі,
  повідомляти в чаті коли і для чого викликається браузер.
- `agent-browser` (окремий CLI, згаданий користувачем) **не встановлений** у
  цьому середовищі й не є Node.js-пакетом цього репозиторію (немає
  package.json) — якщо користувач знову його згадає, уточнити, звідки він
  очікується (глобальний інструмент чи інший репозиторій).

## Як повторити збір каталогів конкурентів (якщо знадобиться оновити)

### carbon.net.ua (SPA, Horoshop-подібний рушій, anti-bot)
1. `curl https://carbon.net.ua/content/export/carbon.net.ua/catalog-sitemap.xml`
   — публічний sitemap, не захищений anti-bot, дає повний список URL товарів.
2. Відфільтрувати `/ru/` дублі й нетоварні URL (напр. батареї, якщо не потрібні).
3. Відкрити ОДНУ товарну сторінку через claude-in-chrome (navigate + wait ~2-3с
   для проходження proof-of-work challenge) — після цього весь домен доступний
   без повторного проходження challenge в тому ж табі.
4. Пройтись рештою URL через `browser_batch` (navigate → wait 2с → get_page_text)
   пачками по 5-8 за раз. Структура сторінки стабільна: назва, артикул,
   ціна, наявність, характеристики (Ø/розмір/вага/колір/поверхня/технологія),
   опис, категорія (breadcrumb) — усе є в тексті `<main>`.
5. Для великих обсягів (100+ сторінок) — делегувати фоновому агенту
   (`Agent` tool, `run_in_background: true`) з чіткою інструкцією писати
   результат інкрементально у текстові файли по 15-20 товарів, щоб не
   втратити прогрес при збої.

### com-posit.com.ua (WordPress, статичні прайс-таблиці, без anti-bot)
1. `curl https://com-posit.com.ua/product-sitemap.xml` — список категорій
   (не окремих товарів — це не WooCommerce з product-per-URL, а сторінки-категорії
   з HTML-таблицями цін).
2. `curl` кожну сторінку категорії (`/carbon-products/tubes`, `/sheets`,
   `/models`, `/paddles`, `/car-tuning` тощо) напряму — дані статичні,
   в HTML, кодування UTF-8 (можливі поодинокі биті байти — читати з
   `errors='replace'`).
3. Парсити `<table>` блоки регулярними виразами (Python `re` — дивись історію
   сесії 2026-08-07 для готових regex-патернів по кожному типу таблиці:
   труби мають грід діаметр×[лакована/нелакована]×[1-9шт/10+шт], пластини —
   товщина×розмір, авіамодельні деталі — 3 різні таблиці з різною структурою).
   Скрипти парсингу не збережені в репо (видалені після використання) —
   писати заново за потреби, орієнтуючись на HTML-структуру в цьому описі.

## Моніторинг цін конкурентів без браузера — `competitor_prices.py`

**З'явився 2026-10-15** на задачу Олександра (СРМ): промоніторити ціни на
електроніку (бренди **Matek** і **Cuav**) й порівняти наші ціни з трьома
конкурентами. Користувач явно попросив **НЕ через браузер** (claude-in-chrome),
а бібліотеками, що емулюють середовище й нормально парсять захищені сайти.

Скрипт на **`curl_cffi`** (імітує TLS-відбиток реального Chrome, `impersonate=`)
+ `beautifulsoup4`. Браузер не запускається взагалі. Залежності:
`pip install curl_cffi beautifulsoup4` (обидві стоять з 2026-10-15).

Запуск: `python3 competitor_prices.py Matek` (або `Cuav`, або будь-який запит).
Функції для імпорту: `scrape_modelistam(q)`, `scrape_ekran(q)`,
`scrape_dronshop(q)`, `export_excel(...)`.

Як пробито кожен сайт (захист у всіх різний):
- **modelistam.com.ua** — без захисту, звичайний GET на
  `/ua/advanced_search_result.php?keywords=<q>`. Картки `.product-thumb__*`,
  код з префіксом `MA-`/`CV-` + model number.
- **ekran.store** — Horoshop-рушій (як carbon.net.ua) з JS proof-of-work, що
  лише ставить **статичну cookie** `challenge_passed=<hash>`. Підставляємо її
  напряму (константа `EKRAN_COOKIE` у скрипті) — браузер не потрібен. Список
  товарів беремо з `catalog-sitemap.xml`, ціну/наявність — з картки
  (`itemprop="price"` / JSON-LD).
- **dron-shop.com.ua** — Prom-рушій за **adm.tools anti-bot** (віддає 429 на
  будь-який звичайний запит). Це повноцінний **hashcash proof-of-work**:
  flow `GET → POST{action:fetch} → POST{action:challenge} →` розв'язати PoW
  `→ POST{action:confirm}`. PoW: перебрати `counter` (uint64 BE), поки
  `SHA-256(nonce + ":" + counter)` не матиме `bits` нульових старших бітів,
  зібрати `solutions` штук. Реалізовано в класі `AdmToolsSession` (~0.13с на
  розв'язання). Картки `.product-thumb`, назва `.h2 a`, ціна `.price`
  (`"2995 <span>3695</span>"` = нова\_ціна `<span>`стара`</span>`).

**ВАЖЛИВО про dron-shop CAPTCHA:** при **частих** запитах підряд adm.tools
ескалює з hashcash-PoW до **візуальної SVG-CAPTCHA**, яку чистим Python не
пройти. Скрипт це ловить (`AdmToolsSession.CaptchaRequired`), зберігає картинку
в `dronshop_captcha.svg` і просить відкрити сайт у браузері вручну. Щоб не
тригерити: не робити burst, тримати паузи (у `scrape_dronshop` ретраї з
`sleep 8s`, між різними запитами/брендами — `sleep 10s`). У нормальному темпі
все проходить стабільно (перевірено: Matek 34 товари, Cuav 23).

Матчинг моделей: строго за model number; **виключати клони**
(`аналог|analog|fly controller`) і аксесуари (`kabel|cable|кабель|mount`), бо
вони засмічують «найдешевшу» ціну (напр. у dron-shop є «H743-WING V3 аналог
Matek» за пів ціни — це НЕ Matek; у ekran кабель до CUAV PMU за 310 грн — це НЕ
модуль). Див. готові regex-патерни в історії сесії 2026-10-15.

Результати задачі 2026-10-15 (закомічені в репо):
- `price_monitoring_matek_cuav.xlsx` — фінальний Excel для клієнта: аркуш

## Важливі домовленості з користувачем (з попередніх сесій)

- Не чіпати файли, залишені з попередніх сесій, без явного запиту користувача
  (напр. `download_images.py`, `photos_part*.zip` — залишені як є).
- **Для скрапінгу конкурентів — спершу бібліотеки (`curl_cffi`), а не браузер.**
  Користувач 2026-10-15 явно попросив НЕ через claude-in-chrome, а бібліотеками,
  що емулюють середовище. claude-in-chrome лишається запасним варіантом (напр.
  коли adm.tools віддасть візуальну CAPTCHA — тоді картинку відкрити користувачу
  в браузері, щоб він пройшов вручну).
- Скріншоти браузерної автоматизації зберігати в `.agent-browser/` (у git ігнор).
- Комітити тільки за явним проханням користувача.
